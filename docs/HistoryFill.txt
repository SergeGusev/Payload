Теперь нам нужно запомнить таблицу btc_5m_history_full следующим образом:

0. Чистим таблицу btc_5m_history_full (TRUNCATE btc_5m_history_full RESTART IDENTITY)
1. Проходим по всем closed/resolved маркетам в истории, включая маркеты с volume = 0 (через API Polymarket)
2. Для каждого из маркетов выполняем следуюющие действия:
2.1. Загружаем в память историю BTC/USDT за время действия маркета (через API Binance), захватив значения минус 5 минут, чтобы гарантированно иметь значения для ближайшей снизу сделки.
2.3. Запоминаем значение btc_start  (последняя сделка <= time_start)- значение USDT на момент старта маркета и time_start - время начала жизни магазина
2.4. Создаём в памяти коллекцию btc_5m_cache, которая будет содержать структуры, совпадающие со структурой btc_5m_history_full
2.5. Инициализируем счётчик секунд sec_counter в -1 секунду (чтобы при первом инкременте стала 1 секунда) 
2.6. Для каждого значения счётчика проводим следующие действия:
2.6.1. 
2.6.2. Если sec_counter станет больше 300, то есть мы вышли за пределы времени жизни маркета плюс 5 секунд, прерываем цикл и выполняем действия после цикла начиная с пункта 2.7. То, что точка 300 не попадёт в результат - не страшно.
2.6.3. Если зsec_counter_rounded находится в рамках времени жизни магазина, то берём значение BTC (последняя сделка <= targetTime) в момент time_start.AddSeconds(sec_counter). Вычисляем разницу btc_diff между полученным значением и значением  btc_start.
 Переводим btc_diff в центы в переменную cents_diff и записываем в btc_rounded значение cents_diff округлённое до 5 
значение центов к нулю. 12 станет 10 и т.д. Для отрицательных значений округление работает также к 0, например, для -12 мы получим -10
2.6.4. Ищем в кеше btc_5m_cache значение с seconds = sec_counter_rounded и cents = btc_rounded. Если не находим - добавляем его со статусом inserted и значениями count = 1, up_count 0, down_count = 0. Если находим и его статус loaded,
   то переводим статус в updated и увеличиваем count на единицу.
2.6.5. Увеличиваем счётчик sec_counter на 5 секунд.
2.7. Запоминаем результат маркета (Up или Down) в переменной result. Если результат по каким-то причинам неизвестен, просто пропускаем запись по этому маркету и переходим к следующему.
2.8. После цикла по магазину проходим по кешу btc_5m_cache и для записей не в статусе loaded увеличиваем на 1 счётчик up_count если result = Up или счётчик down_count если если result = Down.
2.9. Проходим по кешу btc_5m_cache и обновляем в базе записи со статусом updated и добавляем записи со статусом inserted

Как результат этого цикла - заполненная историческими данными таблица btc_5m_history, в которой для каждого значения seconds + cents есть информация о том, сколько раз мы в эту точку попадали, сколько из них выиграло, а сколько проиграло.
